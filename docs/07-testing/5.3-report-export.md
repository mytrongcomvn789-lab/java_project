# Kiểm thử phần 5.3 — Xuất báo cáo Excel/PDF

Ngày kiểm tra: **22/11/2026**, giờ Việt Nam.

## Phạm vi

Phần 5.3 kiểm tra hai API tải báo cáo:

- `GET /api/v1/statistics/orders/export.xlsx`
- `GET /api/v1/statistics/orders/export.pdf`

Hai API dùng chung bộ lọc và dữ liệu của thống kê 5.1. Báo cáo có tổng hợp, dữ liệu theo ngày, tải trạm, khoảng thời gian, múi giờ, mốc ngày, trạm và thời điểm xuất.

## Nội dung issue/PR 5.3

**Tên đề xuất:** `APDDMP-? — 5.3 Xuất báo cáo Excel/PDF`

**Mục tiêu issue:** Xác nhận ứng dụng Java có thể tải hai định dạng báo cáo theo bộ lọc thống kê chung, bảo vệ dữ liệu theo quyền và không tính lại công thức ở exporter.

**Phạm vi cần test trong issue:**

- Tải Excel `export.xlsx` và kiểm tra chữ ký file, tên file, `Content-Type`, `Content-Disposition`, mở được workbook và đúng sheet.
- Tải PDF `export.pdf` và kiểm tra chữ ký file, tên file, `Content-Type`, mở được PDF, tiếng Việt, bảng và nhiều trang.
- Đối chiếu tổng, tỷ lệ, attempt, thời gian giao và dữ liệu theo ngày với API 5.1 bằng cùng `from`, `to`, `dateBasis`, `stationId`.
- Kiểm tra khoảng thời gian, múi giờ `Asia/Ho_Chi_Minh`, mốc ngày, đơn vị, thời điểm xuất và ghi chú định nghĩa trong cả hai file.
- Kiểm tra dữ liệu rỗng, ngày không có đơn, trạm ngoài phạm vi và khoảng ngày tối đa 366 ngày.
- Kiểm tra chưa đăng nhập `401`, tài khoản không phải `LOGISTICS_MANAGER` `403`, tài khoản manager chưa phân công trạm không thấy dữ liệu.
- Kiểm tra dữ liệu text không biến thành công thức Excel; chuỗi bắt đầu `=`, `+`, `-`, `@` phải được bỏ qua làm công thức.
- Chạy `StatisticsIntegrationTest`, `StatisticsPeriodTest`, `StatisticsFormulasTest` và web build.
- Đính kèm file `.xlsx/.pdf` mẫu hoặc ảnh đối chiếu review nếu dữ liệu fixture không chứa bí mật/cá nhân.

**Định nghĩa hoàn thành:** Hai file mở được, số liệu khớp API, bộ lọc và quyền hoạt động ở backend, Unicode/PDF không bị cắt, Excel giữ kiểu số/ngày, test pass, PR có hướng dẫn demo và reviewer đã kiểm tra đầu ra.

## Test backend xuất báo cáo

Test integration riêng phần export nằm trong `StatisticsIntegrationTest`:

- Tạo dữ liệu fixture gồm trạm được phân công và trạm ngoài phạm vi.
- Gọi Excel bằng vai trò `LOGISTICS_MANAGER`.
- Kiểm tra HTTP `200`.
- Kiểm tra `Content-Disposition` có tên file đính kèm.
- Kiểm tra body có độ dài hợp lệ.
- Kiểm tra chữ ký ZIP/Excel `PK`.
- Gọi PDF bằng vai trò `LOGISTICS_MANAGER`.
- Kiểm tra HTTP `200` và body có độ dài hợp lệ.
- Kiểm tra chữ ký `%PDF`.
- Gọi export bằng vai trò `CUSTOMER`: HTTP `403`.
- Gọi export không có Authorization: HTTP `401`.

Các test cũ trong cùng class tiếp tục kiểm tra:

- Tóm tắt theo khoảng ngày.
- Chuỗi theo ngày đủ mọi ngày.
- Tỷ lệ giao, hoàn, hủy.
- Attempt và retry.
- Phạm vi trạm được phân công.
- `stationId` ngoài phạm vi không mở dữ liệu.
- Tải trạm theo khung giờ.
- Hiệu năng trên bộ fixture 3000 đơn.

## Kiểm tra định dạng file

### Excel

Workbook `.xlsx` gồm:

1. `Thông tin`: tiêu đề, khoảng ngày, múi giờ, mốc ngày, trạm, thời điểm xuất, đơn vị và ghi chú.
2. `Tổng hợp`: tổng số đơn, từng nhóm trạng thái, tỷ lệ, attempt, retry và thời gian giao.
3. `Theo ngày`: ngày địa phương và số liệu theo từng ngày.
4. `Tải trạm`: capacity, booked, free, processing, utilization và khung giờ.

Các quy tắc kiểm tra:

- Workbook mở được bởi thư viện đọc ZIP/Excel.
- Nội dung text không được chuyển thành công thức.
- Chuỗi bắt đầu `=`, `+`, `-` hoặc `@` được thêm tiền tố `'`.
- Giá trị số và thời gian vẫn để dưới dạng dữ liệu, không ghép thành chuỗi công thức.

### PDF

PDF được tạo bằng bộ font Unicode nhúng. Nội dung gồm tiêu đề, metadata, bảng tổng hợp, bảng theo ngày và bảng tải trạm. PDF được kiểm tra bằng chữ ký `%PDF` ở đầu response và độ dài body.

Các điều kiện Unicode, nhiều trang và không cắt bảng đã được thiết kế trong exporter, nhưng cần lần kiểm tra trực quan sau bằng trình đọc PDF trên máy nghiệm thu.

## Checklist đối chiếu dữ liệu

Khi reviewer tải file, kiểm tra theo thứ trình sau:

1. So khoảng `from/to`, `dateBasis` và `stationId` trong metadata của file với bộ lọc đã chọn.
2. Mở sheet/bảng tổng hợp và đối chiếu tổng đơn với `GET /api/v1/statistics/orders/summary`.
3. Đối chiếu từng dòng ngày với `GET /api/v1/statistics/orders/daily`.
4. Đối chiếu tải trạm với `GET /api/v1/statistics/stations/load` cùng `stationId` và `at`.
5. Kiểm tra tỷ lệ giao/hoàn/hủy và số attempt bằng chính response API 5.1.
6. Kiểm tra ngày rỗng có dòng 0 trong Excel/PDF.
7. Kiểm tra tên trạm, Unicode tiếng Việt và thời điểm xuất.
8. Thử vai trò không đủ quyền và xác nhận backend không gửi file.

Không đối chiếu bằng công thức tính lại trong Excel/PDF; dữ liệu cần khớp source từ API 5.1.

## Giới hạn và nghiệm thu còn lại

- Chưa nghiệm thu trên dữ liệu vận hành SQL Server thật.

- Chưa kiểm tra trực quan Unicode, nhiều trang PDF và bố cục nhiều dòng thực tế bằng thiết bị đọc PDF.
- Chưa kiểm tra hoàn toàn volume tối đa/giới hạn tải dữ liệu với dữ liệu production.
- Chưa có mobile Flutter export trong phần này; mobile cần dùng chung endpoint khi giai đoạn web/mobile tiếp tục tích hợp.
- Font PDF được nhúng; file font Noto Sans nằm trong repository backend.
- Hiện chưa có file mẫu `.xlsx/.pdf` sinh sẵn trong repository. Đầu ra được tạo trực tiếp bởi API và có thể tải trong runtime.
